ขอบเขตของระบบ (In-Scope vs Out-of-Scope)

การกำหนดขอบเขตฟังก์ชันการทำงานที่ชัดเจนเพื่อประสิทธิภาพและความปลอดภัยสูงสุด

✅ ขอบเขตภายในระบบ (In-Scope)
  • ระบบยืนยันตัวตน Bcrypt Cost 12 + Persistent PostgreSQL Session Store
  • ระบบป้องกัน Brute Force Login Lockout (8 ครั้งใน 10 นาที)
  • Dynamic RBAC 14 Permissions พร้อมตารางสิทธิ์ Dynamic Matrix UI
  • Database Engine Exclusion Constraint ป้องกัน Double-Booking
  • ระบบ Auto-Reject คิวที่เวลาชนกันอัตโนมัติเมื่อมีการอนุมัติรายการใดรายการหนึ่ง
  • การตรวจ Magic Bytes ของไฟล์แนบจริงฝั่ง Server + Anti-IDOR Stream
  • บันทึกประวัติความปลอดภัยและการทำงาน (Security Audit Logging)
⏸️ ขอบเขตนอกระบบสำหรับอนาคต (Out-of-Scope)
  • ระบบชำระเงินค่าเช่าห้อง (เนื่องจากเป็นระบบบริหารจัดการภายในองค์กร)
  • การเชื่อมต่อระบบปฏิทินบุคคลภายนอก (เช่น Google Calendar / Office 365)
  • การควบคุมสวิตช์ไฟหรือกลอนประตูดิจิทัลฮาร์ดแวร์จริง (IoT Hardware)
  • การส่ง SMS แจ้งเตือน (เลือกใช้ In-App Notifications และ Audit Logs แทน)

Authentication & Session Management

มาตรฐานความปลอดภัยระดับองค์กร: การป้องกัน Brute Force, Fixation และ Credential Leakage

🔐 Bcrypt Cost 12 & Zero Leak

• รหัสผ่านเข้ารหัสด้วย Bcrypt Salt Rounds = 12
• ป้องกัน Rainbow Table และพจนานุกรมถอดรหัส
• Zero Credential Leakage: ตัด field password_hash ออกจาก JSON Response และ Audit Log ทุกจุด

💾 PostgreSQL Session Store

• บันทึกลงตาราง user_sessions ผ่าน connect-pg-simple
• เซสชันไม่หลุดเมื่อรีสตาร์ตเซิร์ฟเวอร์
• กำหนด Session Timeout 30 นาที พร้อม Rolling Refresh เมื่อมีการใช้งานต่อเนื่อง

🔄 Session Regeneration

• เมื่อยืนยันตัวตนผ่าน จะสั่ง req.session.regenerate() ทันที
• สร้าง Session ID ใหม่ ป้องกัน Session Fixation Attack

🚫 Brute Force Lockout Guard

• ตรวจจับการพยายามล็อกอินผิดพลาดเกิน 8 ครั้งใน 10 นาที
• ระงับการเข้าใช้งานชั่วคราว 10 นาทีทันที พร้อมบันทึก Security Audit Log

ACL Safety Guards & Integrity Rules

กลไกป้องกันความผิดพลาดของผู้ดูแลระบบ (Fool-Proof Protection)

🚫 ห้ามลบบทบาทที่มีผู้ใช้งานอยู่

หาก Role นั้นยังมีบัญชีผู้ใช้สังกัดอยู่ ระบบจะปฏิเสธการลบทันที ป้องกันการเกิดบัญชีผู้ใช้ลอยเคว้ง (Orphan Users) ที่ไม่มีสิทธิ์ในระบบ

🔒 ห้ามริบสิทธิ์จาก Admin คนสุดท้าย

ระบบมี Guard ป้องกันการปลดสิทธิ์ acl.manage จากผู้ดูแลระบบคนสุดท้าย เพื่อป้องกันอุบัติเหตุการล็อกตัวเองออกจากระบบ (Lockout Prevention)

🔗 Database Foreign Key Constraints

ใช้ ON DELETE CASCADE สำหรับตาราง role_permissions เพื่อล้างสิทธิ์อัตโนมัติ และใช้ ON DELETE RESTRICT สำหรับตารางข้อมูลหลัก ป้องกันข้อมูลสูญหาย

Secure File Upload & Magic Bytes Pipeline

การป้องกันการปลอมแปลงนามสกุลไฟล์และการเข้าถึงไฟล์โดยมิชอบ (Anti-IDOR)

🔍 Magic Bytes Guard

อ่าน 4–8 ไบต์แรกของไฟล์บนดิสก์ เช่น PDF ต้องขึ้นด้วย %PDF (0x25 0x50 0x44 0x46) หากเป็นไฟล์ปลอมจะ ลบไฟล์ทิ้งทันที

🗄️ Outside Public Root

เก็บไฟล์ไว้ที่ uploads/ นอก Web Public Root และเปลี่ยนชื่อเป็น Random UUID ป้องกัน Path Traversal (../../)

🛡️ Anti-IDOR Stream

การเปิดดูไฟล์ต้องผ่าน Route /app/files/:id พร้อมเช็กสิทธิ์ file.view ในระบบ ห้ามเข้าถึงไฟล์โดยตรงผ่าน URL

if (!isValidMagicBytes) {
  fs.unlinkSync(filePath); // ลบไฟล์อันตรายทิ้งทันที
  await logAudit({ action: 'FILE_REJECTED', status: 'DENIED', details: 'Magic bytes mismatch' });
  return res.status(400).send('ตรวจพบลายเซ็นไฟล์ไม่ถูกต้อง');
}

Comprehensive Audit Logging

การบันทึกประวัติความปลอดภัยและการทำงานที่โปร่งใส ตรวจสอบย้อนหลังได้ 100%

📋 ข้อมูลที่บันทึกลงใน audit_logs

• วันที่และเวลาประทับตรา (created_at)
• ผู้กระทำ (user_id, username, role_name)
• การกระทำ (action เช่น LOGIN_SUCCESS, BOOKING_CREATE, ACL_UPDATE)
• แหล่งข้อมูลเป้าหมาย (resource, resource_id)
• สถานะผลลัพธ์ (SUCCESS, FAILED, DENIED)
• ข้อมูลเครือข่าย (ip_address, user_agent)

🔒 มาตรการความปลอดภัยของ Log

• Append-Only: ไม่มี API หรือหน้าจอสำหรับแก้ไขหรือลบ Log
• Zero Credential Leakage: ไม่มีการบันทึกรหัสผ่านหรือ hash ใดๆ
• Fast Query Indexing: สร้าง B-tree Index บน created_at, action, username เพื่อค้นหาย้อนหลังได้อย่างรวดเร็ว

Challenges & Lessons Learned

ความท้าทายทางวิศวกรรมซอฟต์แวร์ที่แก้ไขสำเร็จ และแนวทางการพัฒนาต่อยอด

🛠️ ความท้าทายที่แก้ไขสำเร็จ

• Double-Booking: จัดการด้วย GIST Exclusion Constraint และ Pessimistic Row Lock (SELECT FOR UPDATE)
• Session Loss on Reload: ใช้ connect-pg-simple บันทึกลง PostgreSQL ทำให้เซสชันคงอยู่ตลอดการพัฒนา
• Fake File Injection: ใช้ Buffer Inspection อ่าน Magic Bytes ลึกถึงระดับไบต์จริงของไฟล์

🚀 การพัฒนาต่อยอดในอนาคต

• เชื่อมต่อ LINE Notify / Email แจ้งเตือนสถานะการอนุมัติแบบเรียลไทม์
• ระบบสแกน QR Code หน้าห้องประชุมเพื่อ Check-in ทันทีผ่านสมาร์ตโฟน
• เชื่อมต่อระบบ IoT เปิด/ปิดแอร์และไฟอัตโนมัติตามช่วงเวลาการจอง
